무한히 상호작용 가능한 실시간 월드 시뮬레이터 — 에이전트가 캐릭터 행동과 환경 생성을 함께 조율한다.

생성형 월드 모델은 상호작용 지평(얼마나 오래 일관되게 이어갈 수 있나)·실시간성·다양한 상호작용을 동시에 확보하기 어려웠다.

LingBot-World 2.0은 (1) 인과적(causal) 사전학습으로 품질을 유지한 채 '무한' 상호작용 지평을 확보하고, (2) 실시간 변형을 증류(distill)해 720p·60fps를 구동하며, (3) 공격·궁술·주문·사격 등 다양한 행동과 텍스트 기반 이벤트를 지원한다. (4) 월드 모델에 '에이전트 하니스'를 도입해 pilot 에이전트가 캐릭터 행동을 계획·실행하고 director 에이전트가 새 환경 요소를 생성한다. 14B 본 모델 + 단일 GPU용 1.3B 경량 버전.

방법 상세

LingBot-World 2.0(별칭 LingBot-World-Infinity)은 상호작용형 비디오 월드 모델로, 14B 주력 모델과 단일 GPU 배포를 노린 1.3B 경량 모델을 함께 제공하며 백본은 DiT(Diffusion Transformer)이다. 다만 논문 본문은 기반 모델명을 밝히지 않으며, 'Wan2.2 기반으로 구축(built upon Wan2.2)'이라는 서술은 공식 레포 README에만 존재한다. 핵심은 인과적 월드 모델링(causal world modeling)으로, 결합분포를 p(x₁:ₜ|a₁:ₜ)=∏ₜ p(xₜ|x<t, a≤t)로 인수분해해 각 상태를 과거 관측과 현재 입력에만 의존시키는 자기회귀(autoregressive) 생성으로 무한(hour-level) 지평의 일관성을 노린다. 이를 위해 teacher forcing과 양방향 어텐션을 결합한 MoBA(Mixture of Bidirectional and Autoregressive) 어텐션 마스크, 카메라 포즈용 Plücker embeddings(6D 좌표), 텍스트/제어 신호 주입용 AdaLN(adaptive layer normalization)을 사용한다. 학습은 2단계로, (1) conditional flow-matching(속도 예측) 목적함수로 인과적 사전학습을 하고, (2) Consistency Distillation과 DMD(Distribution Matching Distillation)로 다단계 확산을 소수 스텝(few-step) 생성기로 증류하는 사후학습을 거쳐 720p/60fps 실시간을 달성하며, DMD는 self-rollout 궤적 위에서 최적화해 누적 드리프트를 억제한다. 추론 시 동적 KV cache 관리(context-adaptive scheduling)로 무한 롤아웃을 지원한다. 에이전트 하니스는 저수준 물리·렌더링을 담당하는 비디오 생성 모델(Pilot=DiT)과 거시적 의미 규칙·인과추론으로 이벤트를 제안하는 VLM(Director)로 구성되며, Director는 마스크 없는 직접 의미 상호작용과 SAM 기반 추적 보조 객체 상호작용의 두 모드를 지원한다. 다만 실시간 지표(GPU 종류·지연시간)와 정량 벤치마크 수치는 본문에 명시되어 있지 않다.

비디오 생성 모델은 콘텐츠 창작(시각적 화려함) 위주라, 로봇 제어에 필요한 계산 효율·물리적 현실성과는 도메인 불일치가 있다.

임바디드 지능에 맞춘 DiT 기반 비디오 사전학습. 아키텍처는 dense 대신 MoE로 용량·추론효율 균형을 잡아 처음부터 스케일업하고, 데이터는 조작·내비게이션·1인칭 로봇 영상을 인터넷 영상에 증강하는 프로파일링 엔진을 쓰며, 학습은 미학·프롬프트 준수를 넘어 '물리적 합리성·과제 완수'를 강제하는 다차원 보상을 도입한다.

방법 상세

LingBot-Video는 DiT(Diffusion Transformer) 기반 비디오 생성 패러다임을 embodied intelligence(체화 지능)용으로 재설계하고, dense 대신 Mixture-of-Experts(MoE) 구조를 채택해 모델 용량(modeling capacity)과 추론 효율(inference efficiency)의 트레이드오프를 개선했다(초록 확인). 공개 가중치는 dense 1.3B와 MoE 30B-total/3B-active(30B-A3B) 두 변종으로, 토큰당 30B 중 약 3B만 활성화하며 레포/HF 카드는 동일 품질 dense 대비 '~3x faster inference'를 주장한다(측정 프로토콜은 미공개). 두 변종 모두 T2I·T2V·TI2V·Refinement을 지원한다(README 확인; 초안의 'Refiner는 MoE 전용'은 근거 없어 정정). 학습 데이터는 'data profiling engine'이 인터넷 비디오에 manipulation·navigation·egocentric 등 로봇 지향 영상을 대규모로 증강해(대규모 웹 비디오 + 70,000+시간 embodied 데이터) 행동(action)과 세계 동역학(world dynamics)에 대한 사전지식을 심는 방식이다(초록·README). 정렬(alignment)은 표준 지표인 심미성(aesthetics)·모션 일관성(motion consistency)을 넘어 물리적 타당성(physical rationality/realism)과 과제 완수(task completion)까지 강제하는 다차원 보상(multi-dimensional reward)으로 수행한다(초록·README). 프롬프트 리라이터로 Qwen3.6-27B를 base VLM으로 두고 구조화 JSON 출력용 LoRA 어댑터를 얹은 2단계 파이프라인을 제공한다(README; 초안의 '자동 negative prompt 생성'은 미확인이라 삭제). 다만 전문가(expert) 개수, 토큰당 활성 전문가 수, 라우팅 방식, DiT 레이어/차원, 보상 최적화 기법(GRPO/DPO 등)과 학습 컴퓨트는 fetch 가능한 자료(초록·README·HF·GitHub)에 없어 원문 본문(paper.pdf) 확인이 필요하다 — arXiv HTML 404, PDF 10MB 초과, alphaXiv 403으로 본문 파싱 불가.

방법 상세

AutoDev은 자율 AI 에이전트가 IDE 전반의 기능(파일 편집·검색·빌드·실행·테스트·git)을 직접 조작하도록 오케스트레이션하는 프레임워크로, 네 개의 핵심 축(Conversation Manager, Tools Library, Agent Scheduler, Evaluation Environment)으로 구성된다. (1) Conversation Manager는 사용자·에이전트 대화를 관리하며 하위 모듈로 에이전트 응답에서 명령·인자를 정해진 포맷으로 파싱하는 Parser, 실행 환경의 출력을 처리·구조화하는 Output Organizer, 종료 시점을 결정하는 Conversation Conclusion을 둔다. (2) Agent Scheduler는 Round Robin / Token-Based / Priority-Based 협업 알고리즘으로 다중 에이전트를 조율한다. (3) Tools Library는 File Editing(write/edit/insert/delete), Retrieval(grep/find/ls/embedding 기반 스니펫 검색), Build & Execution, Testing & Validation(테스트·린터·버그탐지), Git(commit/push/merge에 대한 세분화된 권한 설정), Communication(talk/ask/stop)의 6개 명령 범주를 제공한다. 방법 상세

CALM은 이산 토큰(RVQ codec) 대신 연속 잠재(latent)를 자기회귀적으로 예측하는 오디오 언어모델이다. 구조는 세 부분으로, (1) 큰 causal Transformer backbone(음악은 MusicGen Medium 계열 1.35B, 스피치 continuation은 Helium-1 pretrained 기반 2B)이 각 timestep에서 문맥 임베딩 z_long을 만들고, 학습 시 입력 latent에 노이즈를 주입(x̃_s=√k_s·ε+√(1−k_s)·x_s)해 추론 시 오차 누적(error accumulation)과 divergence를 완화한다. (2) 직전 K개(음악 K=10, 약 0.4s)의 clean latent만 보는 경량 short-context Transformer z_short를 더해(Z_s=z_long+z_short) 지역적 디테일을 보존한다(스피치는 ablation상 K가 결정적 하이퍼파라미터가 아님). (3) 확산(diffusion) head 대신 약 10M 규모의 소형 MLP consistency model head가 단일 스텝(1-step)으로 다음 프레임 latent를 생성한다(x̂_s=f_φ(x=ε,t=1,Z_s)). 잠재 공간은 RVQ를 대체하는 VAE-GAN(스피치 32차원 causal, temporal/frequency 재구성+adversarial+feature matching+KL+스피치는 WavLM semantic distillation)이며 프레임레이트는 스피치 12.5Hz·음악 25Hz(32kHz mono)다. 손실은 TrigFlow류 continuous-time consistency 목적함수(x_t=cos(t)·x+sin(t)·ε, t∈[0,1])를 쓴다. 핵심 기법으로 z_long을 N=8회 재사용해 노이즈/타임스텝을 독립 샘플링하는 Head Batch Multiplier, 연속판 temperature sampling인 Gaussian Temperature Sampling(스피치 τ=0.8), 잠재 조건에 CFG를 거는 Latent CFG(TTS α≈1.5), CFG teacher를 소형 student로 옮기는 Latent (Self-)Distillation(LSD, TTS 24→6 layer)이 있다.

방법 상세

옵티마이저 모델이 점수화된 롤아웃을 입력받아 단일 스킬 문서에 경계가 있는(bounded) add/delete/replace 편집을 생성한다. 각 편집은 보류(held-out) 검증 점수를 '엄격히 향상'시킬 때만 채택되어, 확률적·휴리스틱이 아닌 결정론적 수용 기준을 갖는다. 텍스트 학습률 예산이 단계별 편집 범위를 제한하고, 거부된 편집은 버퍼에 저장해 중복 탐색을 막으며, 에폭 단위 slow/meta 업데이트로 점진적·안정적으로 수렴한다. 최적화는 오프라인에서 일어나 배포 시 추가 모델 호출이 없다.

실험 셋업

  • 벤치마크 6종, 타깃 모델 7종(GPT-5.5 포함)
  • 실행 환경 3종: 직접 대화 / Codex 에이전트 루프 / Claude Code
  • 비교군: 인간 작성, 일회성 LLM 생성, Trace2Skill, TextGrad, GEPA, EvoSkill

데이터셋

  • 6개 에이전트 벤치마크 + 인접 수학 벤치마크(전이 평가) — 52개 (모델,벤치,환경) 조합 (에이전트 태스크)

한계 · 비판

  • 초록 수준에서는 명시적 한계 서술이 제시되지 않음 (저자 인정)
  • 옵티마이저 모델 자체의 품질·비용에 성능이 의존할 수 있음 (추가 의문)
  • 도메인마다 검증셋과 점수 함수를 설계해야 해 적용 부담이 있음 (추가 의문)
