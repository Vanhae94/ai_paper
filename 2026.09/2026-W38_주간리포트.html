방법 상세

TradingAgents는 실제 트레이딩 회사를 모사한 LLM 멀티에이전트 프레임워크로, 7개 역할을 5개 팀으로 조직한다. (1) 애널리스트 팀(Analyst Team)은 펀더멘털(fundamental)·감성(sentiment)·뉴스(news)·기술적(technical) 분석가가 각자 구조화 리포트를 생성한다. (2) 리서처 팀(Researcher Team)은 강세(bull)/약세(bear) 연구자가 자연어 토론(natural language debate)을 n라운드 진행하고, 진행자(facilitator) 에이전트가 토론 이력을 검토해 우세 관점을 선택·기록한다(원문 표현 'facilitator ... selects the prevailing perspective'). (3) 트레이더(Trader)가 이를 종합해 매매 신호를 도출한다. (4) 리스크 관리 팀(Risk Management Team)은 공격적(aggressive)·중립(neutral)·보수(conservative) 세 관점이 토론해 노출을 조정한다. (5) 펀드 매니저(Fund Manager)가 최종 승인·집행한다. 에이전트 간 통신은 '구조화 리포트'를 1차 채널로, '자연어 대화'를 2차 채널로 쓰는 하이브리드 방식이며, 공유 글로벌 에이전트 상태(global agent state)와 메모리로 과거 결정 맥락을 유지한다(명시적 reflection 모듈 여부는 본문 확인 필요). 모델은 2계층(two-tier) 전략으로, 추론 집약 노드(분석·연구·트레이딩)에는 심층사고(deep-thinking) o1-preview를, 요약·데이터 변환·검색 등에는 신속사고(quick-thinking) gpt-4o/gpt-4o-mini를 배정하고, 전 에이전트는 ReAct 프롬프팅 프레임워크를 따른다(논문 명시). LangGraph는 논문 본문이 아니라 공식 오픈소스 레포/문서에서 구현 스택으로 명시된다('built with LangGraph').

재현 가능성

코드 공개 (github.com/TauricResearch/TradingAgents, Python, CLI+패키지, 조회 시점 약 94.6k 스타 — 변동값)가중치 해당 없음 — 자체 학습 가중치 없이 OpenAI/Anthropic/Google/xAI/DeepSeek/Qwen/Ollama 등 상용·로컬 LLM API를 호출하는 구조데이터 부분 공개 — Yahoo/FinnHub/EODHD/Reddit 등 공개 API로 수집(API 키 필요), 정제·전처리 세부는 재현 시 재구성 필요라이선스 Apache-2.0 (레포 확인)

연구 아이디어 생성부터 실험·감사까지 연결해, 그럴듯한 결론이 증거 없이 통과하지 못하게 한다.

자율 연구 에이전트가 긴 워크플로를 실행할 수 있어도 아이디어가 과학적으로 타당하고 실험 결과가 신뢰할 만하다는 보장은 없다. 자동화된 실험의 오류나 과장된 해석이 다음 단계의 전제가 되면 연구 전체가 빠르게 잘못된 방향으로 갈 수 있다.

Idea Generation 단계는 최신 연구 신호와 축적된 도메인 지식을 합치고, 다른 문제로 옮길 수 있는 기계적 통찰을 찾아 검증 가능한 연구 계획을 만든다. 여러 모델이 후보를 생성하고 교차 검토(cross-review)해 아이디어를 다듬는다. Idea Execution 단계에서는 조정된 에이전트들이 실험을 분해·구현·진단하며, 독립적인 증거 기반 검토가 결과를 확인한 뒤에만 계속·수정·종료를 결정한다.

방법 상세

AutoResearch는 자율 연구를 아이디어 생성과 아이디어 실행이라는 두 단계의 증거 중심 루프로 분해한다. 아이디어 생성 단계는 논문·코드 저장소·기술 미디어·소셜 신호와 내부 큐레이션 지식베이스를 함께 검색하고, 여러 모델이 한 연구 신호를 서로 다른 문제 영역의 메커니즘으로 옮길 수 있는지 독립적으로 제안한다. 현재 구현은 3개의 frontier 모델이 후보를 만들고 3개의 리뷰어가 각각을 평가하며, 최소 2개의 긍정 리뷰를 받은 후보만 실행 계획으로 넘긴다. 출력은 가설 h와 실행 가능한 계획 p의 쌍이며, 계획에는 검증 가능한 수용 기준과 필요한 실험이 포함된다. 아이디어 실행 단계에서는 계획을 의존성 그래프 G_p=(T,R)로 바꾸고, 선행 작업이 끝난 태스크를 병렬 실행한다. 매 라운드의 상태는 계획·코드·로그·측정값·체크포인트·리뷰·근거·결정을 영속 기록하며, 실행자와 별도의 리뷰어·비평자가 신선한 컨텍스트에서 결과를 다시 점검한다. 리뷰어는 구현과 프로토콜의 충실도를, 비평자는 결과가 주장과 실제로 연결되는지를 확인하고 PASS/PARTIAL/FAIL을 반환한다. 실패하면 DIAGNOSE-REVISE-RERUN으로 되돌아가며, 근거가 존재할 때만 주장을 수용한다(Accept(c) => 존재하는 e가 Supports(e,c)=1). 마지막 결정은 Continue, Revise, Scale, Stop 중 하나로 기록하고 부정적 결과도 유효한 연구 결과로 보존한다.

실험 셋업

  • 비교 시스템: The AI Scientist, Agent Laboratory, R&D-Agent, AutoResearchClaw. 동일한 목표와 과제별 실험 계약을 사용하고, 최종 성과뿐 아니라 감사에서 확인된 문제 이벤트 수와 산출물 무결성을 함께 비교.
  • RSICD 교차모달 검색: mean Recall이 기본 32.84에서 단계별로 33.89, 34.04, 최종 34.69로 상승(+1.85). 제안 아이디어는 전역 정렬, 텍스트 유도 국소 집계, 엔티티-위치 연관을 결합.
  • RSICD 감사 결과: AutoResearch의 감사 확인 문제 이벤트는 5건으로 보고되었고 R&D-Agent 11건, AutoResearchClaw 15건, Agent Laboratory 18건, The AI Scientist 27건과 비교됨. 이 수치는 정확성 자체가 아니라 감사 범위에서 발견된 문제 사건 수임.
  • 행렬 곱셈 최적화: 1024x1024 FP32, 200ms 미만, 두 참조 구현 대비 상대 오차 1e-5 미만, 실제 wall-clock 10회에서 변동계수 20% 미만을 계약으로 설정. 초기 실험은 CPU 시간과 경과 시간을 혼동해 안정성 검증에 실패했고, 프로토콜을 고친 뒤 3.4ms·626 GFLOPS·약 58배의 속도 여유를 보고.
  • 행렬 곱셈 감사 이벤트: AutoResearch 4건, R&D-Agent 5건, Agent Laboratory 5건, AutoResearchClaw 7건, The AI Scientist 8건으로 보고.
  • Kaggle형 태스크: Titanic 정확도 0.822 -> 0.843으로 목표 0.830을 넘어 확장, House Prices RMSLE 0.2008 -> 0.1251로 개선했지만 목표 0.120에 미달해 수정, Disaster Tweets F1 0.763 -> 0.805로 상승했으나 목표 0.835에 못 미치고 개선이 정체되어 중단·부정적 결과 보존.
  • 규모 관찰: 단일 서버(2x Intel Xeon Platinum 8563C, 98코어/196스레드, 8x NVIDIA L20, 944GiB RAM)에서 7일 동안 약 2,584개 후보 아이디어를 만들고 약 355개를 실험 큐에 넣었으며, 약 22개 자동 실험과 약 14개 경험적으로 검증된 아이디어를 보고.
  • 실행 루프의 핵심 측정은 아이디어 수보다 증거 연결과 감사 이벤트에 놓여 있다. 그러나 컴포넌트별 ablation, 반복 실행 분산, 실제 토큰·벽시계 비용은 본문 표에서 충분히 분리되어 있지 않음.

데이터셋

  • 외부 연구 신호 코퍼스 — 논문·코드 저장소·기술 미디어·X/Xiaohongshu 등, 정확한 규모와 샘플링 비율은 미공개 (최신 연구 동향과 구현 신호 탐색)

한계 · 비판

  • 시스템은 외부 연구 신호의 품질과 범위, 축적된 지식, 명시적인 실험 기준에 의존하며, 이 입력이 부족하면 좋은 연구 아이디어나 결론을 보장할 수 없음. (저자 인정)
  • 자동화된 연구 시스템의 결론이 항상 옳다고 보장하지 않으며, 실험 결과와 해석은 독립적인 검토와 재현 가능한 증거를 필요로 함. (저자 인정)
  • 현재의 규모 실험은 한 대의 대형 서버에서 수행되었고, 장기적으로는 실행 결과가 지식 상태에 다시 반영되는 지속적 피드백이 필요함. (저자 인정)
  • 실험 기준을 충족하지 못한 결과나 부정적 결과도 연구 기록으로 남겨야 하며, 모든 아이디어를 끝까지 실행하는 구조가 아님. (저자 인정)
  • 감사에서 발견된 문제 이벤트가 적다는 사실은 결론의 정확성이나 재현성을 직접 측정하지 않는다. 감사 범위, 오류 탐지 민감도, 문제의 심각도가 함께 공개되지 않아 5건 대 11~27건을 품질 순위로 읽으면 안 됨. (추가 의문)
  • 비교 시스템과 외부 모델의 실행 하니스·프롬프트·예산·재시도 조건이 완전히 동일한지 제3자가 확인하기 어렵다. 따라서 성능과 감사 이벤트 비교는 시스템 전체 비교로 해석해야 하며, 순수 모델 능력의 대결로 환산하기 어려움. (추가 의문)
  • RSICD의 최종 mean Recall 34.69는 시작점 32.84보다 +1.85 개선이지만, 아이디어 생성·실험·감사 각 구성요소의 기여를 분리한 ablation이 부족하다. 여러 모델을 더 많이 호출한 효과와 연구 아이디어 자체의 효과도 분리되지 않음. (추가 의문)
  • 반복 횟수, 신뢰구간, 시드, 작업별 변동이 충분히 보고되지 않아 작은 과제군에서의 수치 차이를 일반화하기 어렵다. 약 2,584개 후보와 약 22개 자동 실험의 선택 과정도 공개되지 않아 선택 편향을 배제할 수 없음. (추가 의문)
  • 태스크당 토큰 비용·벽시계 시간·GPU 비용과 사람 검토 비용이 분리 보고되지 않는다. 다중 생성·교차 리뷰·재실행을 포함한 시스템이 더 정확해도 연구자 입장에서 경제적인지는 아직 검증되지 않음. (추가 의문)
  • 연구 주제는 RSICD, 시스템 최적화, 소규모 Kaggle 태스크에 집중되어 있다. 장기 과학 실험, 실험실 장비, 비정형 질적 연구, 다른 학문 분야에서도 같은 감사 구조가 작동하는지는 확인되지 않음. (추가 의문)
  • 공식 저장소는 Alpha 단계이며 넓은 도구 권한과 폐기 가능한 격리 환경을 전제로 한다. 코드·셸·외부 신호를 함께 다루므로 프롬프트 인젝션, 자격증명 노출, 악성 의존성, 잘못된 연구 산출물의 배포 위험은 별도 보안 경계가 필요함. (추가 의문)
  • 아이디어 생성의 '메커니즘 전이'가 실제로 새롭고 유용한 통찰인지, 기존 연구의 조합인지, 그리고 후속 심사에서 살아남는지는 논문의 단기 자동 실험 수치만으로 판단하기 어려움. (추가 의문)

재현 가능성

코드 공개 — 공식 GitHub 저장소 EvoMap/AutoResearch에 신호 수집·아이디어 생성·리뷰·계획·실행 상태·비평·blind review를 디스크에 기록하는 워크플로가 포함됨. Claude Code와 Ralph Loop 기반 실행 경로, 복구 가능한 체크포인트와 결과 파일 구조를 제공.가중치 해당 없음 — 자체 사전학습 모델 가중치를 공개하는 논문이 아니라 여러 frontier 모델과 코딩 에이전트를 조합하는 시스템. 사용하는 모델 API와 모델별 접근 권한이 재현성에 영향을 줌.데이터 부분 공개 — 실행 예시와 연구 신호 처리 구조는 공개되지만 내부 큐레이션 지식베이스, 전체 SFT/RL·프롬프트 코퍼스, 실제 7일 실행 로그와 선택된 2,584개 후보 전체는 공개되지 않음. RSICD와 공개 Kaggle 태스크는 외부에서 접근 가능.라이선스 Apache-2.0 (공식 EvoMap/AutoResearch 코드 저장소 기준). 사용하는 모델 API·데이터·외부 저장소는 각각의 이용 조건을 별도로 따라야 함.

서빙이나 추론 가중치 재현보다 오케스트레이션 재현이 핵심인 시스템 논문이다. 저장소를 실행하면 파일 기반 상태·리뷰·체크포인트 패턴은 확인할 수 있지만, 동일한 모델 엔드포인트·시점별 외부 신호·비공개 지식베이스·대규모 GPU 자원이 없으면 논문의 수치와 동일한 결과를 기대하기 어렵다. README도 결론의 정확성을 보장하지 않는다고 명시한다.

📌 내 학습 포인트

  • 연구 자동화 프롬프트에 반드시 수용 기준을 먼저 적어라. 목표 점수·허용 오차·반복 횟수·측정 시계를 실행 전에 고정하고, 결과가 목표를 넘었을 때만 '개선'이라고 부르면 에이전트가 유리한 지표만 골라 결론을 만드는 일을 줄일 수 있다.
  • 실행자와 검증자를 분리하고 검증자에게 실행 궤적 전체를 보여주지 않는 설계를 실험해보라. 새 컨텍스트의 리뷰어가 코드·로그·산출물만 근거로 주장을 반박하게 하면, 에이전트가 스스로 만든 설명을 사실처럼 재사용하는 오류를 줄일 수 있다.
  • 연구 상태를 대화 컨텍스트가 아니라 파일 기반 레코드로 외부화하라. 계획 그래프, 실험 상태, 근거, 결정, 실패 원인을 각각 구조화해 두면 컨텍스트 압축이나 재시작 뒤에도 왜 다음 실험을 해야 하는지 복원할 수 있다.
  • 감사 이벤트 수와 성능 점수를 별도 축으로 기록하라. 오류가 적게 발견된 시스템이 더 정확하다고 단정하지 말고, 독립 재현 성공률·검증 가능한 주장 비율·비용·사람 검토 시간을 함께 평가하는 습관이 필요하다.

방법 상세

AutoDev은 자율 AI 에이전트가 IDE 전반의 기능(파일 편집·검색·빌드·실행·테스트·git)을 직접 조작하도록 오케스트레이션하는 프레임워크로, 네 개의 핵심 축(Conversation Manager, Tools Library, Agent Scheduler, Evaluation Environment)으로 구성된다. (1) Conversation Manager는 사용자·에이전트 대화를 관리하며 하위 모듈로 에이전트 응답에서 명령·인자를 정해진 포맷으로 파싱하는 Parser, 실행 환경의 출력을 처리·구조화하는 Output Organizer, 종료 시점을 결정하는 Conversation Conclusion을 둔다. (2) Agent Scheduler는 Round Robin / Token-Based / Priority-Based 협업 알고리즘으로 다중 에이전트를 조율한다. (3) Tools Library는 File Editing(write/edit/insert/delete), Retrieval(grep/find/ls/embedding 기반 스니펫 검색), Build & Execution, Testing & Validation(테스트·린터·버그탐지), Git(commit/push/merge에 대한 세분화된 권한 설정), Communication(talk/ask/stop)의 6개 명령 범주를 제공한다. (4) Evaluation Environment는 Docker 컨테이너 안에서 모든 명령을 안전하게 실행하는 샌드박스다. 사용자는 YAML 설정으로 에이전트별 허용/제한 명령(guardrails)과 페르소나·역할(예: Developer, Reviewer)을 선언하며, 기본 설정 또는 세분화 권한을 선택할 수 있다. 평가에서는 gpt-4-1106-preview 단일 에이전트를 사용했고, 에이전트가 명령을 내면 환경이 실행 후 파일 내용·컴파일러 출력·빌드/테스트 로그·정적분석 결과를 다시 대화 이력으로 되돌려 반복(iterative) 개선하는 폐루프 구조다.

방법 상세

AuK는 음성 생성과 오디오 편집을 하나의 instruction-conditioned foundation model로 통합한다. 의미 조건은 Qwen2.5-Omni 기반 멀티모달 LLM에서 얻고, 24kHz waveform을 50Hz의 64차원 latent로 바꾸는 공동 학습 Audio VAE가 세밀한 음향 조건을 표현한다. 생성기는 FLUX 계열의 hybrid rectified-flow Transformer로, 앞쪽 M개의 dual-stream MMDiT 블록에서 semantic stream과 acoustic target/reference stream을 함께 주의집중시킨 뒤 N개의 single-stream DiT 블록에서 통합 처리한다. 사전학습은 speech generation만 쓰는 50k-step 워밍업 후 generation과 editing을 함께 쓰는 600k-step 단계로 진행하며, 두 번째 단계의 태스크 비율은 음성 생성 28.10%, content editing 23.02%, enhancement/separation 23.17%, paralinguistic editing 21.75%, acoustic editing 3.96%다. 음성 생성에는 flow matching, 편집에는 지시·참조 오디오·마스크 구간 조건을 사용하고, 편집 선호 최적화와 음성 생성 보상 기반 RL을 별도로 적용한다. 후처리에서는 consistency initialization으로 학생 모델을 시작한 뒤 task-routed Decoupled DMD를 적용한다. separation 태스크는 분포 증류에서 제외하고 clean latent에 대한 지도 회귀를 사용해 분리 품질이 무너지지 않게 한다. 최종 AuK는 32 NFE와 CFG 2.0을 쓰고, AuK-Flash는 consistency와 DMD로 4 NFE까지 줄이며 CFG를 제거한다.

  • 화자 음성 복제와 감정·억양·내용 편집을 하나로 제공하는 모델은 사칭·동의 없는 음성 조작·오디오 허위정보 위험이 있다. 논문에서 안전 필터, provenance, 워터마킹, 악용 평가가 핵심 기여로 다뤄지지 않는 점은 실제 배포에서 별도 보완이 필요함. (추가 의문)
  • 중국어·영어 중심 평가가 많아 저자들이 말하는 다국어·cross-task 전이의 범위를 넓게 일반화하기 어렵다. 방언·저자원 언어·코드스위칭·장시간 대화에서 성능은 추가 검증이 필요함. (추가 의문)

재현 가능성

코드 공개 — 공식 GitHub Tencent-Hunyuan/AuK에 src, 학습·추론 스크립트, 문서와 체크포인트 사용 경로가 포함되며 AuK와 AuK-Flash 추론을 지원. 2026년 9월 기준 MLX Apple Silicon, CPU offload, SGLang-Omni 경로도 저장소에서 안내됨.가중치 공개 — 공식 Hugging Face의 tencent/AuK 및 tencent/AuK-Flash 체크포인트와 저장소의 다운로드·실행 안내가 제공됨. Qwen2.5-Omni 기반 의미 인코더와 관련 의존 모델은 각각의 모델 카드 조건을 따름.데이터 부분 공개 — 코드·가중치·평가 방법은 공개되지만 30.3억 instruction-audio 인스턴스, 195만 시간 감독, 사내 억양·편집·합성 데이터 전체는 배포되지 않음. 공개 벤치마크와 일부 데이터 구축 절차로 추론 재현은 가능하나 학습 데이터 재현은 불가.라이선스 공식 저장소 LICENSE와 Hugging Face 모델 카드에 코드·가중치별 조건이 제시되므로 상업 이용 여부는 해당 문서를 각각 확인해야 함. 논문·의존 모델·데이터 원천의 라이선스가 하나로 자동 통합되는 것은 아님.

AuK는 공개 추론 실험을 시작하기 좋은 오픈 릴리스지만, 256 GPU 학습 인프라와 비공개 데이터 때문에 처음부터 같은 모델을 재학습하는 수준의 재현성은 없다. 또한 AuK 본체와 Prompt Enhancer, Qwen2.5-Omni 계열, 외부 평가 모델의 버전을 함께 고정해야 논문 수치에 가까운 결과를 얻을 수 있다.

📌 내 학습 포인트

  • 하나의 오디오 모델에 의미 조건과 음향 조건을 분리해 넣는 설계를 공부하라. 텍스트 지시는 MLLM의 의미 표현으로, 참조 음성·마스크·목표 파형은 VAE latent로 처리하면 생성과 편집을 같은 backbone에 얹을 수 있다는 구조적 교훈이 있다.
  • 멀티태스크 학습에서 작업별 데이터 비율과 출력 목표를 명시적으로 관리하라. AuK의 5개 task mixture처럼 생성·편집·향상·분리의 샘플 비중을 기록하고, 전체 평균 대신 작업별 지표를 따로 남겨 한 작업의 개선이 다른 작업의 붕괴를 가리지 않게 해야 한다.
  • few-step 증류를 적용할 때 하나의 DMD 목적함수를 모든 태스크에 강제하지 마라. AuK가 separation을 task-routed 경로로 분리한 것처럼, 생성·편집·분리는 품질 보존 조건이 다르므로 증류 목적과 평가를 작업별로 설계해야 한다.
  • 속도 보고에는 반드시 기능·품질 표를 붙여라. 32-step 대비 4-step의 NFE와 wall-clock만 기록하지 말고 WER, 화자 유사도, 내용·스타일·음향 편집 정확도, 실패 유형을 함께 측정해야 실제 배포 가능한 가속인지 판단할 수 있다.

방법 상세

OpenHands(구 OpenDevin)는 코딩·명령줄·웹 브라우징을 사람 개발자처럼 수행하는 AI 에이전트를 만들기 위한 오픈 플랫폼으로, 핵심 추상화는 단일 step(self, state: State) 함수와 이벤트 스트림(event stream)이다. 이벤트 스트림은 과거 행동(Action)과 관찰(Observation)을 시간순으로 누적한 State의 핵심 요소로, 사용자 지시/피드백·멀티에이전트 위임 메타데이터까지 담는다. 행동 원시 타입은 IPythonRunCellAction(샌드박스 내 Python 실행), CmdRunAction(bash 실행), BrowserInteractiveAction(BrowserGym DSL 기반 웹 조작), 그리고 AgentDelegateAction·MessageAction·AgentFinishAction 등으로 정의된다. 실행 격리는 Agent Runtime으로, Docker 샌드박스 위에서 bash 쉘, Jupyter IPython 서버, Playwright 기반 Chromium을 제공한다. AgentSkills는 기본 bash/Python으로 얻기 어려운 유틸리티 툴박스로 edit_file, scroll_up/scroll_down, parse_image(비전-언어 모델 기반), parse_pdf 등을 제공한다. 멀티에이전트 협업은 AgentDelegateAction으로 구현되어 범용 CodeActAgent가 웹 태스크를 BrowsingAgent에게 위임할 수 있으며, 커뮤니티 에이전트 구현은 AgentHub에 모인다. 이 이벤트 스트림 + Docker 런타임 + AgentSkills + 위임 구조가 새 에이전트 구현·평가를 표준화하는 프레임워크를 이룬다.

  • 안전(safety) 측면 우려 및 현 AI 에이전트가 실세계 태스크를 신뢰성 있게 수행하기 어렵다는 점 인정 (저자 인정)
  • SWE-Bench 전체(2,294)가 아닌 Lite(300) 위주 보고이며 절대 성능(26.0%)은 신뢰성 있는 실무 자동화 수준과는 거리가 있어 상한 해석에 주의 (추가 의문)
  • 최고 성능이 폐쇄형 상용 LLM(gpt-4o, claude-3.5-sonnet)에 크게 의존 - '오픈 플랫폼' 정체성과 성능 원천 사이에 긴장. 오픈웨이트 모델 성능은 본문 확인 필요 (추가 의문)
  • 각 벤치마크의 세부 세팅(shot 수, 재시도 정책, 프롬프트) 및 baseline 공정성은 표를 직접 대조해야 완전 판단 가능 (추가 의문)
  • 버전이 빠르게 바뀌어(v1.5 vs v1.8) 논문 수치와 현재 레포 성능/설계가 어긋날 수 있어 재현 시 커밋+모델 버전 고정 필요 (추가 의문)
  • 도메인별 최고점은 여전히 전문 에이전트/전용 학습 모델에 미달 - '제너럴리스트'의 대가로서 범용성-성능 트레이드오프가 명시적으로 존재 (추가 의문)

📌 내 학습 포인트

  • 에이전트 프레임워크 설계 시 '행동(Action)-관찰(Observation) 이벤트 스트림 + 단일 step(state: State) 함수' 추상화를 벤치마킹하라 - 새 에이전트/멀티에이전트 위임(AgentDelegateAction)을 최소 변경으로 붙일 수 있는 확장점이 된다.
  • 코드 실행은 Docker 이미지 기반 격리 런타임(bash + IPython + Playwright)으로 감싸라 - 안전성과 환경 재현성을 동시에 확보하는 실전 패턴을 그대로 차용할 수 있다.
  • 직접 재현 시 논문 수치가 아닌 특정 커밋 + 명시된 모델 버전(claude-3.5-sonnet@20240620 등)으로 고정하고, SWE-Bench는 Lite(300)로 소규모 검증 후 확장하라 - 전체 2,294 실행은 약 $6.9k 비용이 든다.

Claude 종합 코멘트

OpenHands(구 OpenDevin)의 가장 큰 기여는 특정 SOTA 점수가 아니라, 이벤트 스트림·Docker 런타임·AgentSkills·에이전트 위임(AgentDelegateAction/AgentHub)을 표준화해 '누구나 코딩·CLI·웹을 다루는 에이전트를 만들고 15개 벤치마크로 재평가'할 수 있게 한 오픈 인프라 그 자체다. MIT 라이선스에 32K stars, 188+ 기여자로 커뮤니티 채택이 확실하고 ICLR 2025 채택(arXiv Comments 확인)이라는 학술 검증도 받았다. 다만 SWE-Bench Lite 26.0%, WebArena 15.5%, MiniWoB++ 40.8% 같은 절대 성능은 실무 자동화와 거리가 있고, 특히 웹 도메인은 전용 학습 모델 CC-NET 91.1%에 크게 미달해 '제너럴리스트'의 성능 타협이 뚜렷하다. 또한 최고 성능이 폐쇄형 상용 LLM에 종속되어 '오픈 플랫폼' 정체성과 성능 원천 사이에 긴장이 있다. 종합하면 성능 논문이라기보다 '에이전트 연구의 공통 실험대'를 제시한 인프라 논문으로 읽는 것이 정확하며, 후속 SE 에이전트/데이터 연구의 사실상 표준 하네스가 되었다는 점에서 영향력이 크다.

📋 이번 주 요약

이번 주 6편은 놀라울 만큼 명확하게 갈렸다. TradingAgents·AutoResearch·AutoDev·OpenDevin 등 4편(66.7%)이 에이전트와 실행 시스템이고, YuE·AuK 2편(33.3%)은 음악·음성 생성이다. 에이전트 축에서는 단순 툴 호출보다 신뢰할 수 있는 실행이 중심이다.
